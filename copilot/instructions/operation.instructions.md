コードやドキュメントを書く時は、常に対象読者を念頭に置き、この会話の文脈を知らない読者にも理解できる内容にすること。禁止事項や補足事項は、必要性を明確に説明できる場合にのみ含めること。

既存のコードとドキュメントに矛盾を見つけた時は、コードの挙動と慣例を信頼できる情報源とみなして作業を進め、発見した全ての矛盾を最終的な応答の中で列挙すること。

`npm` の代わりに `pnpm` を、`npx` の代わりに `pnx`（エイリアス: `pnpm dlx`、`pnpx`）を使用すること。この環境の Node.js は `pnpm runtime …`（pnpm 11.0 以降）でインストールされており、`npm` と `npx` は利用できない。

パッケージスクリプトは必ず `pnpm run …` で実行し、組み込みコマンドとして解釈されないようにすること。

依存関係の変更には可能な限りパッケージマネージャーを使用し、マニフェストファイルとロックファイルの整合性を保つこと。

Git コミットまたはタグの作成に失敗した時は、エラーを報告して指示を待つこと。この環境では 1Password SSH エージェントによるコミットおよびタグの署名が有効になっているが、ユーザーが席を外しており SSH キーアクセス要求がタイムアウトすることがある。
